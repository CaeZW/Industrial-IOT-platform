# Industrial IoT Platform

On-premise Industrial IoT platform for machine monitoring, data acquisition,
historian, alarms, commands, production, reports, maintenance, energy and
future industrial applications.

## Approved architecture

```text
Angular + TypeScript
        │
   REST / WebSocket
        │
        ▼
NestJS + TypeScript
   │             │
   │ SQL         │ MQTT
   ▼             ▼
PostgreSQL    Mosquitto
                 │
                 ▼
              Node-RED
                 │
                 ▼
       Industrial equipment
```

An additional supported path is:

```text
MQTT-capable Device
        │
        ▼
     Mosquitto
        │
        ▼
      NestJS
```

## Hard boundaries

- Node-RED is the OT Integration Gateway.
- Node-RED MUST NOT access PostgreSQL.
- NestJS is the only application component allowed to access PostgreSQL.
- Angular communicates only with NestJS.
- Angular does not connect directly to MQTT or PLCs.
- MQTT is the integration/event bus.
- WebSocket is the browser realtime channel.
- REST is the request/response channel.
- Commands are authenticated, authorized, validated and audited by NestJS before dispatch.
- PDF reports are generated by NestJS, never by Node-RED.
- PLCs remain responsible for deterministic control, interlocks and safety logic.
- The application must not bypass PLC safety/interlock logic.

## Development Docker environment

```text
Node-RED        http://localhost:51880
PostgreSQL      localhost:55432
Mosquitto MQTT  localhost:51883
MQTT WebSocket  localhost:59001
```

Containers:

```text
docker-nodered
docker-postgre
docker-mosquitto
```

Networks:

```text
iot-messaging
├── docker-mosquitto
└── docker-nodered

application-data
└── docker-postgre
```

For local development, `application-data` is a private bridge and PostgreSQL is
published exclusively on `127.0.0.1:55432`. This allows local NestJS processes,
migrations and pgAdmin to connect without exposing PostgreSQL to the LAN.

Node-RED MUST NOT have a direct route to PostgreSQL.

Production must remove the PostgreSQL host-port mapping and use an internal
application-data network. The development Compose file is not a production
deployment definition.

## Local environment

Development configuration is stored in `.env`.

`.env` MUST NOT be committed.

Do not create or maintain `.env.example` or `.env.template`. This project keeps
local environment configuration only in `.env`; variable names are documented
without publishing secret-bearing template files.

Never commit:

- passwords;
- MQTT credentials;
- database credentials;
- private keys or certificates;
- production data;
- production secrets;
- generated PDFs.

The infrastructure must remain demonstrably functional:

- PostgreSQL starts and reports healthy;
- Mosquitto starts and accepts publish/subscribe;
- Node-RED starts and requires editor authentication;
- Node-RED communicates with Mosquitto;
- Docker volumes persist data;
- Docker networks remain isolated;
- Node-RED cannot access PostgreSQL;
- the production installation remains unaffected.

Automated application tests belong primarily to implementation sprints. Infrastructure validation in Sprint 0 is performed through explicit operational checks.

Repository and shared-contract checks:

```bash
pnpm lint

```

network isolation:

```bash

```

Use `pnpm infra:validate:start` when the local stack is stopped.

## Common Docker commands

Start:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml up -d
```

Stop:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml stop
```

Start stopped containers:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml start
```

Remove containers/networks without removing volumes:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml down
```

Remove containers and local volumes:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml down -v
```

Use `down -v` only when intentionally destroying local development data.

Status:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml ps
```

Logs:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml logs -f
```

Service logs:

```bash
docker logs -f docker-postgre
docker logs -f docker-mosquitto
docker logs -f docker-nodered
```

Resource usage:

```bash
docker stats docker-postgre docker-mosquitto docker-nodered
```
