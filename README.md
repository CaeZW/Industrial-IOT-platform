# Industrial IoT Platform — Sprint 0

On-premise Industrial IoT platform for machine monitoring, data acquisition,
historian, alarms, commands, production, reports, maintenance, energy and
future industrial applications.

## Approved architecture

```text
Angular + TypeScript
        │
   REST / WebSocket
        │
        ▼
NestJS + TypeScript
   │             │
   │ SQL         │ MQTT
   ▼             ▼
PostgreSQL    Mosquitto
                 │
                 ▼
              Node-RED
                 │
                 ▼
       Industrial equipment
```

An additional supported path is:

```text
MQTT-capable Device
        │
        ▼
     Mosquitto
        │
        ▼
      NestJS
```

## Hard boundaries

- Node-RED is the OT Integration Gateway.
- Node-RED MUST NOT access PostgreSQL.
- NestJS is the only application component allowed to access PostgreSQL.
- Angular communicates only with NestJS.
- Angular does not connect directly to MQTT or PLCs.
- MQTT is the integration/event bus.
- WebSocket is the browser realtime channel.
- REST is the request/response channel.
- Commands are authenticated, authorized, validated and audited by NestJS before dispatch.
- PDF reports are generated by NestJS, never by Node-RED.
- PLCs remain responsible for deterministic control, interlocks and safety logic.
- The application must not bypass PLC safety/interlock logic.

## Local environment

Development configuration is stored in `.env`.

`.env` MUST NOT be committed.

Do not create or maintain `.env.example` unless the project later needs a multi-developer/shared setup. The current local project intentionally keeps environment configuration in `.env` plus documentation.

Never commit:

- passwords;
- MQTT credentials;
- database credentials;
- private keys or certificates;
- production data;
- production secrets;
- generated PDFs.

## Common Docker commands

Start:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml up -d
```

Stop:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml stop
```

Start stopped containers:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml start
```

Remove containers/networks without removing volumes:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml down
```

Remove containers and local volumes:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml down -v
```

Use `down -v` only when intentionally destroying local development data.

Status:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml ps
```

Logs:

```bash
docker compose --env-file .env -f infra/compose/compose.yaml logs -f
```

Service logs:

```bash
docker logs -f docker-postgre
docker logs -f docker-mosquitto
docker logs -f docker-nodered
```

Resource usage:

```bash
docker stats docker-postgre docker-mosquitto docker-nodered
```
